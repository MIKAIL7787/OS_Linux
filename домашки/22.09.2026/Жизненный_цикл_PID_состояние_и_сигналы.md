# Процессы и потоки в операционных системах

Процессы и потоки — это фундаментальные абстракции ОС, которые обеспечивают эффективное распределение ресурсов и позволяют распараллеливать вычисления.

## 1. Уровни вычислительных единиц

В современных ОС можно выделить четыре уровня управления задачами:

| Уровень | Что это | Особенности |
| :--- | :--- | :--- |
| Задание (Job) | Группа процессов с общими квотами и лимитами. | Применяется редко. |
| Процесс (Process) | Выполняющаяся программа; контейнер для ресурсов. | Запрашивает все ресурсы, кроме процессора. |
| Поток (Thread) | Единица планирования в ядре, которой выделяется время CPU. | В простейшем случае процесс = один поток. |
| Волокно (Fiber) | «Лёгкий» поток, полностью управляемый в пользовательском пространстве. | Используется редко. |

## 2. Что потоки делят, а что имеют своё

Потоки внутри одного процесса работают с общей памятью, но у каждого есть собственные структуры для выполнения кода:

| Общее для всех потоков процесса | Индивидуальное для каждого потока |
| :--- | :--- |
| • Адресное пространство<br>• Глобальные переменные<br>• Открытые файлы<br>• Дочерние процессы<br>• Сигналы и их обработчики<br>• Данные об использовании ресурсов | • Счётчик команд (Program Counter)<br>• Регистры процессора<br>• Стек<br>• Текущее состояние |

## 3. Жизненный цикл и состояния потока

Поток создаётся, после чего циклически переходит между тремя основными состояниями:
1. **Готовность** — поток создан, стоит в очереди и ждёт процессор.
2. **Выполнение** — планировщик выбрал поток, и он исполняется на CPU.
3. **Ожидание** — поток заблокирован системным вызовом или ожиданием ввода-вывода.

### Когда ОС вмешивается в планирование:
* Закончился квант времени активной задачи.
* Задача выполнила блокирующий системный вызов (ввод-вывод, доступ к занятому ресурсу).
* Задача освободила ресурс, которого ждали другие потоки.
* Периферийное устройство завершило операцию ввода-вывода.
* Возникло внутреннее прерывание (ошибка в коде задачи).

## 4. Алгоритмы планирования

Способы распределения процессорного времени зависят от типа ОС:

* **Интерактивные системы:**
  * *Циклическое (квантование)* — каждому потоку выделяется фиксированный интервал времени.
  * *Приоритетное* — сначала выполняются наиболее важные потоки.
  * *Гарантированное* — ОС следит за балансом и делит время поровну между пользователями.
  * *Лотерейное* — ресурсы распределяются случайно по выданным «билетам».
  * *Справедливое* — учитывает, кому принадлежит процесс.
* **Системы реального времени:**
  * Главный критерий — реактивность (жёсткое соблюдение заданных интервалов).
  * *Алгоритм Лью — Лейланда* — классический подход, при котором задача с наименьшим периодом получает наивысший приоритет.

## 5. Синхронизация и межпроцессное взаимодействие (IPC)

Когда несколько потоков одновременно обращаются к общим переменным, возникает риск **гонок** (взаимных состязаний), из-за чего результат программы становится непредсказуемым.

### Ключевые понятия и инструменты:
* **Критическая секция** — участок программы, работающий с общими данными; в ней в каждый момент должен находиться только один поток.
* **Способы взаимного исключения:** запрет прерываний, неделимые блокирующие переменные, мьютексы и семафоры Дейкстры (с операциями P и V).
* **Механизмы обмена данными (IPC):** каналы (pipes), очереди сообщений, почтовые ящики, сокеты и разделяемая память.

## 6. Проблема взаимных блокировок (Deadlocks)

**Взаимная блокировка** (тупик, дедлок) — ситуация, когда несколько процессов блокируют друг друга: каждый удерживает одни ресурсы и бесконечно ждёт доступа к другим.
